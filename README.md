# funds-helper

个人使用的基金理财工具箱（Web）。第一个工具：**QDII 基金额度查询**。

> 解决一个具体问题：**「我想买的这只 QDII，今天还能买多少？」**

---

## 工具箱定位

一个可持续扩展的「工具箱」外壳 + 若干独立工具。每个工具解决一个具体的投资决策问题，
共享同一套数据源接入、缓存、落库、任务调度与前端框架。

| 工具 | 解决什么问题 | 状态 |
|---|---|---|
| **QDII 额度** | 「我想买的这只 QDII，今天还能买多少？」 | ✅ 可用 |
| **美元份额** | 「我想用美元买基金，全市场有哪些美元份额、现在还能不能买？」 | ✅ 可用 |
| 后续工具 | 待定 | 规划中 |

## 快速开始

```bash
pnpm install
cp .env.example .env          # 本地默认 JOBS_ENABLED=false
pnpm dev                      # 后端 :8787 + 前端 :5173
```

打开 <http://localhost:5173>。首次进列表页会拉一次上游数据（约 4 MB / 735 只 QDII），
之后 30 分钟走缓存。

生产部署（单容器同时托管 API 与前端）：

```bash
pnpm build                    # 构建前端到 apps/web/dist
pnpm start                    # 后端会一并托管前端静态资源，访问 :8787
```

服务器常驻（Docker）：

```bash
cp .env.example .env          # compose 会读取它（建议 JOBS_ENABLED=true）
docker compose up -d --build
```

SQLite 落库文件通过 volume 挂在宿主机 `./data`，容器重建不丢历史。

> ⚠️ **Docker 产物尚未在本环境验证过**（开发机没有 docker，无法构建镜像）。
> 基础镜像 tag、入口命令、环境变量与 volume 路径都逐一核对过，
> 但首次 `docker compose up` 仍需你实际跑一次确认。**已验证的生产路径是 `pnpm build && pnpm start`**。
> 部署后无鉴权，仅限内网/局域网；公网访问必须加反向代理鉴权或走 VPN。

### 常用命令

| 命令 | 说明 |
|---|---|
| `pnpm dev` | 后端 + 前端并行开发 |
| `pnpm verify` | typecheck + lint + 测试（离线、秒级） |
| `pnpm smoke` | **端到端冒烟**：起真实服务 + 打真实上游，19 项检查（需联网） |
| `pnpm test` | 仅测试 |
| `pnpm build` | 构建前端 |

> `smoke` 与 `verify` 不可互相替代：前者验证「真实 Node 运行时能不能起来、端到端通不通」，
> 后者验证逻辑正确性。详见 [`docs/design/architecture.md`](docs/design/architecture.md) §10.4。

## 功能

**额度列表**

- **双维度归类**：24 个「地区/市场」× 14 个「主题」，维内多选取并集、维度间取交集
  —— 直接回答「美国的、医药生物的 QDII 还有多少能买？」
- **额度筛选** ≤10 元 / ≤100 元 / ≤1000 元 / ≤1 万 / ≤100 万
- **状态筛选** 可买 / 开放申购 / 限大额 / 暂停申购 / 场内交易 / 全部
- **份额币种** 默认人民币（屏蔽渠道不售的美元份额 0 值噪声）
- 搜索（代码 / 名称）、4 种排序、**筛选条件写入 URL 可分享**

**详情抽屉**（点击任意基金）

- 购买建议置顶：额度与状态提醒、**同基金其它份额类别可直达**、A/C 成本结构说明、赎回费红线
- 当前额度（含**该条额度的采集时刻**）
- 净值走势（近1月~近3年）＋ 区间涨幅与**最大回撤**
- 分周期收益对比同类平均、沪深300、同类排名
- 季度规模、资产配置、持有人结构
- 主要成分（联接基金自动回退展示底层 ETF）
- 最近限购公告（可跳转原文）

**场内溢价**：86 只场内 QDII 的溢价排行（实测最高 27%），评估「场外买不到就转战场内」的代价。

**额度变更**：与上一交易日对比，累积出额度收紧/放宽的历史记录
—— 上游没有历史接口，这部分完全靠工具自己落库。

## 架构

```
apps/server      Fastify 后端（工具注册 + QDII/美元份额路由 + 定时任务）
apps/web         React + Vite 前端（工具箱外壳 + 工具页面）
packages/shared  前后端共享的类型契约（Zod）
packages/core    领域逻辑（纯函数：归一化 / 归类 / 排序 / 币种与份额判定）
packages/sources 上游数据源适配器（天天基金各接口）
packages/db      SQLite 持久化（node:sqlite + 版本化迁移）
```

**几个关键取舍**（完整论证见 [`docs/design/architecture.md`](docs/design/architecture.md)）：

- **无构建步骤**：Node 原生执行 TS，`node src/index.ts` 就是生产运行方式；
  `erasableSyntaxOnly` 保证语法在 strip-only 模式下可运行
- **`node:sqlite` + 手写 SQL**：零原生编译、零 ORM 依赖
- **三层读路径**：进程内缓存 → SQLite → 上游；上游故障时返回陈旧快照并显式标记 `stale`
- **上游解析**：行级宽松（脏行不致整批失败）、结构级严格（列数变化立刻报错）
- **fixture 测试**：真实响应存盘，上游改版时测试立刻失败而不是线上静默出错

新增一个工具 = 新增一个目录切片 + 在注册表加一行，不改动框架代码。
