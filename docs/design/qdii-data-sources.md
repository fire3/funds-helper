# QDII 基金数据接口文档

> 本文档记录 **QDII 基金限购额度** 相关公开数据接口的逆向调研结果。
> 所有接口均在 `2026-09-14` 实测通过，并标注了实测样本。
>
> 内容自 `qdii-helper/docs/api.md` 迁移而来，**剔除实现语言细节**，
> 只保留与语言无关的接口事实、字段语义与踩坑结论。
> 用于本项目 `packages/sources/src/eastmoney/` 的实现与 fixture 采集。
>
> ⚠️ 这些接口都是 **非官方公开 API**（天天基金 / 东方财富 的前端自用接口），
> 没有 SLA、没有版本兼容承诺，字段和路径可能随时变更。请低频调用，勿用于商业分发。

## 0. 快速选型

| 需求 | 推荐接口 | 单次成本 | 备注 |

## 1. 术语与状态枚举

### 1.1 申购状态（`申购状态` / `SGZT`）

实测取值集合（全市场去重）：

| 取值 | 含义 | 对限购查询的意义 |
|---|---|---|
| `开放申购` | 正常开放，无限额 | 无限购 |
| `限大额` | 限大额申购 | **核心关注**，需看日累计限定金额 |
| `暂停申购` | 暂停申购 | 当前不可买入 |
| `场内交易` | 只能二级市场买卖（ETF/LOF） | 不受申赎额度限制，但受溢价影响 |
| `封闭期` | 封闭运作 | 不可申购 |
| `认购期` | 正在募集 | 不可申购 |
| `""`（空） | 数据缺失 | 需回退到接口 B/C |

赎回状态（`赎回状态` / `SHZT`）是**另一套枚举**，取值与申购不同（`开放赎回` 而非 `开放申购`），
不要复用同一个枚举类型：

| 取值 | 含义 |
|---|---|
| `开放赎回` | 可赎回 |
| `暂停赎回` | 暂停赎回 |
| `场内交易` | 场内买卖 |
| `封闭期` / `认购期` | 不可赎回 |
| `""`（空） | 数据缺失 |

### 1.2 「无限额」哨兵值（**最关键的一个坑**）

`日累计限定金额` 用一个大整数表示「无限额」，而不是空值：

| 观测值 | 含义 |
|---|---|
| `100000000000` (1e11) | 无限额 |
| `10000000000` (1e10) | 无限额（债券类常见） |
| `9999999999` | 无限额（等价形态） |
| `0` | 视状态而定：`限大额` 时为「0 元/日」；美元份额常出现 |
| 其余数值 | 真实日累计限额（单位：元） |

**判定阈值**：实测真实限额最高仅 **50,000,000（5 千万）**，
因此 `>= 1e8` 即可安全视为「无限额」。

`status == "开放申购"` 时 `limit` 通常为 1e11，应归一化为「无限额」而非具体数字。

### 1.3 QDII 口径（**重要**）

`基金类型` 字段里，QDII 基金分散在 **两类标签** 中，只匹配 `QDII-` 前缀会漏掉一大半：

| 标签 | 实测数量 |
|---|---|
| `QDII-混合偏股` | 127 |
| `QDII-普通股票` | 87 |
| `QDII-纯债` | 60 |
| `QDII-混合灵活` | 29 |
| `QDII-商品` | 23 |
| `QDII-混合债` | 22 |
| `QDII-FOF` | 9 |
| `QDII-混合平衡` | 8 |
| `QDII-REITs` | 5 |
| **`指数型-海外股票`** | **365** ← 指数型 QDII 全部在这里 |

```
QDII 全集 = 基金类型.startswith("QDII-") OR 基金类型 == "指数型-海外股票"
          = 370 + 365 = 735 只（实测无重叠）
```

`270042 广发纳斯达克100ETF联接人民币(QDII)A` 这种典型 QDII 的 `基金类型` 是
`指数型-海外股票`，**不含 "QDII" 字样**。

### 1.4 份额币种

同一只基金常有多个份额类别，限额币种不同：

- `…人民币` / 无后缀 → 限额单位为 **元**
- `…美元现汇` / `…美元现钞` / `(QDII)美元A` → 限额单位为 **美元**
- 美元份额在天天基金渠道通常不销售，常出现 `日累计限定金额 = 0`

做汇总统计时应剔除 `美元` / `现汇` / `现钞` 关键字，否则会被大量 0 值拉偏。

**标记覆盖率**（实测 334 只含币种关键字的 QDII）：

| 标记 | 数量 | 示例 |
|---|---|---|
| `人民币` | 152 | `华夏全球股票(QDII)(人民币)` |
| `美元现汇` | 90 | `嘉实美国成长股票美元现汇` |
| `美元` | 65 | `广发纳斯达克100ETF联接美元(QDII)A` |
| `美元现钞` | 17 | `嘉实全球互联网股票美元现钞` |
| `现汇` / `现钞` | 3 / 3 | `华夏恒生ETF联接现汇` |
| `美汇` / `美钞` | 2 / 2 | `摩根富时发达市场REITs指数(QDII)美汇` |

> `美汇`/`美钞` 这种简写很容易被漏掉，漏掉后摩根那两只会被误判为人民币份额。

**「人民币」必须优先判定**：`中银美元债债券(QDII)人民币A`、`汇添富美元债债券(QDII)人民币A`
是 **人民币份额**，只是投资标的为美元债，名称中的「美元」描述的是**投资方向而非份额币种**。
实测全量 QDII 名称中，同时含「美元」与「人民币」的有 **12 只**（真·人民币份额）。

## 2. 接口 A：全市场基金申购状态（主接口）

一次性拿到全市场所有基金的申购/赎回状态与限购额度，是限购查询工具的**首选数据源**。

```
GET https://fund.eastmoney.com/Data/Fund_JJJZ_Data.aspx
```

### 2.1 请求参数

| 参数 | 值 | 说明 |
|---|---|---|
| `t` | `8` | **固定为 8**，表示申购状态数据集 |
| `page` | `1,50000` | `起始页,每页条数`；给足够大即为全量 |
| `js` | `reData` | 返回 `var reData=...` 形式的 JS 变量 |
| `sort` | `fcode,asc` | 排序字段与方向 |

### 2.2 请求头

```
User-Agent: Mozilla/5.0
Referer: https://fund.eastmoney.com/Fund_sgzt_bzdm.html
```

### 2.3 实测响应

- HTTP `200`，`Content-Type: text/html; charset=utf-8`
- 响应体约 **4.1 MB**，`record` 值为 **27538** 行
- 响应体是 **JS 对象字面量，不是合法 JSON**（部分 key 无引号）

```
var reData={datas:[["000001","华夏成长混合","混合型-灵活","1.2350","09-14","开放申购","开放赎回","","10.0","100000000000","1.0","1","0.15%"], ... ],record:"27538",pages:"1",curpage:"1",showday:["2026-09-14","2026-09-11"]}
```

### 2.4 解析要点

`datas` 内层行是数组，可以直接 JSON 解析；**只有外层 key 无引号**，因此：

1. **不要** `JSON.parse` 整个响应体 —— 必然失败
2. 截取 `datas:[` 与 `],record:` 之间的子串，单独解析该数组（27538 行，每行 13 列）
3. 尾部 `record` / `pages` / `curpage` / `showday` 四个 key 逐个提取；
   `showday[0]` 是**数据日期**

```
datas 起始 = indexOf("datas:[") + len("datas:")
datas 结束 = indexOf("],record:") + 1
```

> 也可以在开头做一次正则把 `{datas:` 替换为 `{"datas":`，但**尾部还缺 4 个 key**，
> 截取数组仍是最稳的做法。

### 2.5 字段字典（每行 13 列）

| # | 字段 | 类型 | 示例 | 说明 |
|---|---|---|---|---|
| 0 | 基金代码 | string | `270042` | 6 位 |
| 1 | 基金简称 | string | `广发纳斯达克100ETF联接人民币(QDII)A` | 含份额后缀 |
| 2 | 基金类型 | string | `指数型-海外股票` | 见 §1.3 |
| 3 | 最新净值/万份收益 | string→float | `8.1177` | 货币基金为万份收益 |
| 4 | 最新净值报告时间 | string | `09-11` | **仅 MM-DD，无年份**。QDII 常滞后 T-1/T-2 |
| 5 | 申购状态 | string | `限大额` | 见 §1.1 |
| 6 | 赎回状态 | string | `开放赎回` | 见 §1.1 |

## 3. 接口 B：单基金实时信息（移动端）

单只基金最全的实时字段，**且支持 CORS**，适合前端直连。

```
GET https://fundmobapi.eastmoney.com/FundMNewApi/FundMNBasicInformation
```

### 3.1 请求参数

| 参数 | 值 | 说明 |
|---|---|---|
| `FCODE` | `270042` | 基金代码 |
| `deviceid` | `1` | 任意字符串 |
| `plat` | `Android` | 平台标识 |
| `product` | `EFund` | 产品标识 |
| `version` | `6.2.8` | 版本号，随意 |

### 3.2 跨域（实测）

```
HTTP/1.1 200 OK
Access-Control-Allow-Origin: *
Access-Control-Allow-Headers: Content-Type
Access-Control-Allow-Methods: GET,POST,PUT,DELETE,OPTIONS
```

→ 纯前端（静态页 + fetch）即可直连，无需自建后端。**但注意**：接口 B 只能一次查一只，
**列全量必须用接口 A，而接口 A 不支持跨域**（见 §13 结论）。因此本项目仍需要后端。

### 3.3 限购相关字段

响应结构：`{ "Datas": { ... }, "ErrCode": ..., "Success": true }`

## 4. 接口 C：F10 交易状态页

单只基金的**完整交易规则**，含持仓上限等接口 A/B 没有的字段。

```
GET https://fundf10.eastmoney.com/jjfl_270042.html
```

### 4.1 实测响应

HTTP `200`，约 46 KB HTML。关键单元格（`<td>` 平铺，需配对解析）：

| 标签 | 实测值（015641） |
|---|---|
| 申购状态 | `开放申购` |
| 赎回状态 | `开放赎回` |
| 定投状态 | `支持` |
| **申购起点** | `10.00元` |
| 定投起点 | `10.00元` |
| **日累计申购限额** | `无限额` |
| 首次购买 | `10.00元` |
| 追加购买 | `10.00元` |
| **持仓上限** | `无限额` |
| 最小赎回份额 | `1.00份` |
| 部分赎回最低保留份额 | `1.00份` |
| 买入确认日 | `T+1` |

### 4.2 解析要点

页面是「标签 `<td>` → 值 `<td>`」交替结构，**正则配对**即可：

```
匹配 `<td class="th...">标签</td>` 紧跟 `<td>值</td>` 的模式
→ 去掉标签内 HTML → 得到 { 标签: 值 } 映射
```

- 限额值有两种形态：文字 `无限额` 或 `1,000.00元`，需分别处理
- 页面同时含费率表格，正则时注意不要串行匹配

### 4.3 适用场景

补全「持仓上限」等字段；或作为 A/B 接口的交叉校验。

## 5. 接口 D：基金公告（限购原因 / 生效日期）

QDII 限购的**权威口径**来自基金公司公告。该接口可按公告类型筛选。

```
GET https://api.fund.eastmoney.com/f10/JJGG
```

### 5.1 请求参数

| 参数 | 值 | 说明 |
|---|---|---|
| `callback` | `cb` | JSONP 回调名 |
| `fundcode` | `270042` | 基金代码 |
| `pageIndex` | `1` | 页码（从 1 开始） |
| `pageSize` | `20` | 每页条数 |
| `type` | `5` | 公告类型，见下表 |

### 5.2 `type` 枚举（实测）

| type | 内容 | 实测标题样例 |
|---|---|---|
| `1` | 全部 / 招募说明书类 | `…联接基金(QDII)更新的招募说明书` |
| `2` | 分红类 | `…基金收益分配公告` |
| `3` | 定期报告 | `…2026年中期报告` / `…2026年第2季度报告` |
| `4` | 人事调整 | `…基金经理变更公告` |
| **`5`** | **申购赎回类（限购公告）** | `…人民币份额调整大额申购…业务限额的公告` |
| `6` | 公司级通知 | `…旗下基金2026年中期报告提示性公告` |
| `7` | 空 | — |

> **`type=5` 是限购查询的入口**：暂停/限制大额申购的公告全部在此。

## 7. 接口 F：场内行情（含折价率/溢价率）

QDII ETF/LOF 无法场外申购时，溢价率是决策关键。实测 QDII ETF 普遍**大幅溢价**。

### 7.1 批量列表

```
GET https://push2delay.eastmoney.com/api/qt/clist/get
```

| 参数 | 值 |
|---|---|
| `pn` | 页码 |
| `pz` | 每页条数 |
| `po` / `np` | `1` / `1` |
| `fltt` | `2`（**输出十进制小数，不加则返回放大整数**） |
| `invt` | `2` |
| `fid` | 排序字段，如 `f3` |
| `fs` | 板块，`b:MK0021,b:MK0022,b:MK0023,b:MK0024`（沪深 ETF+LOF） |
| `fields` | `f12,f14,f2,f3,f402` |

实测 `total = 1604`。

### 7.2 单只 / 批量指定代码

```
GET https://push2delay.eastmoney.com/api/qt/ulist.np/get?fltt=2&fields=f2,f12,f14,f18,f402&secids=1.513500,0.159941
```

`secids` 格式：`{市场}.{代码}`，**`1` = 上交所，`0` = 深交所**。
（实测代码以 `5` 开头的为沪市，其余为深市。）

### 7.3 字段字典

| 字段 | 含义 | 实测（513500） |
|---|---|---|
| `f2` | 最新价 | `2.656` |
| `f3` | 涨跌幅 % | `-0.19` |
| `f4` | 涨跌额 | `-0.005` |
| `f12` | 代码 | `513500` |
| `f13` | 市场（1=沪, 0=深） | `1` |
| `f14` | 名称 | `标普500ETF博时` |
| `f18` | 昨收 | `2.661` |
| **`f402`** | **折价率 %（负值 = 溢价）** | `-8.24` |
| `f403` | 区间涨跌幅 % | `21.44` |

### 7.4 `f402` 语义验证（**必读**）

用「T-1 单位净值」作为基准复算：

| 代码 | 价格 `f2` | 净值 `DWJZ` | 溢价 = (价格-净值)/净值 | `f402` |
|---|---|---|---|---|
| 513500 | 2.656 | 2.4542 | **+8.22%** | **-8.24** |
| 513100 | 2.191 | 1.9831 | **+10.48%** | **-10.47** |
| 159941 | 1.624 | 1.4848 | **+9.37%** | **-9.36** |

→ 结论：`f402 = (净值 − 价格) / 净值 × 100 = −溢价率`。
`f402` 为负说明**场内价格高于净值（溢价）**。QDII ETF 溢价 8%~10% 是常态。

实测最高溢价（`2026-09-14`）：

| 代码 | 名称 | 价格 `f2` | 净值 `DWJZ` | 复算溢价 | `f402` |
|---|---|---|---|---|---|
| 159509 | 纳指科技ETF景顺 | 2.799 | 2.2751 | **+23.03%** | **-22.97** |
| 159501 | 纳指ETF嘉实 | 2.083 | 1.8627 | **+11.83%** | **-11.82** |
| 159513 | 纳斯达克100ETF大成 | 1.766 | 1.6560 | **+6.64%** | **-6.60** |

> 溢价 **23%** 意味着：场外限购 10 元时转战场内，等于多付两成成本。
> 这是 QDII 限购查询必须同时给出溢价率的原因。

### 7.5 域名可用性

| 域名 | 实测 |
|---|---|
| `push2.eastmoney.com` | 主域名，偶尔连接超时 |
| `push2delay.eastmoney.com` | 备用（延时行情），实测稳定 |

建议**主备自动切换**。

## 8. 接口 G：净值走势 / 规模 / 配置（pingzhongdata）

单只基金详情页的**全量数据包**，一次请求即可拿到全历史净值、季度规模、资产配置、
持有人结构与基金经理。是「看走势、看规模、看仓位」的首选。

```
GET https://fund.eastmoney.com/pingzhongdata/{code}.js
```

### 8.1 请求头与响应

| 项 | 值 |
|---|---|
| `Referer` | `https://fund.eastmoney.com/{code}.html` |
| HTTP | `200`，`application/javascript` |
| 体积 | 约 **518 KB**（实测 270042），UTF-8 **带 BOM** |
| 格式 | JS 文本，`/*注释*/var Name = <json>;` 逐块排列，**不是合法 JSON** |

### 8.2 解析要点

每个值内部不含分号（实测），因此按 `var Name = ...;` 逐块截取后可直接解析：

```
用正则匹配 /var\s+([A-Za-z_$][\w$]*)\s*=\s*(.+?);/g（跨行、非贪婪）
逐个尝试 JSON.parse，失败的块（如函数定义）直接跳过
```

实测 270042 可解析出 **26 个块**。

### 8.3 关键块字典

| 块名 | 结构 | 说明 |
|---|---|---|
| `Data_netWorthTrend` | `[{"x":1344960000000,"y":1.0,"equityReturn":0,"unitMoney":""}, ...]` | **全历史单位净值**，3392 点；`x` 为毫秒时间戳。`unitMoney` 是当日除权事件原文（`拆分：每份基金份额分拆3.0份` / `每份派现金0.0430元`），**必须保留**——单位净值会因分拆/分红机械下调（见 `etf-tool.md` §13） |
| `Data_ACWorthTrend` | `[[1344960000000, 1.0], ...]` | 累计净值（分拆/分红后仍连续，详情卡的复权口径用它） |
| `Data_fluctuationScale` | `{"categories":["2026-06-30",...],"series":[{"y":122.23,"mom":"25.81%"},...]}` | **季度净资产规模（亿元）** |
| `Data_assetAllocation` | `{"series":[{"name":"现金占净比","data":[...]},{"name":"净资产","type":"line","data":[...]}],"categories":[...]}` | 资产配置（最新季度） |
| `Data_holderStructure` | `{"series":[{"name":"机构持有比例","data":[0.66,...]},...],"categories":[...]}` | 持有人结构 |
| `Data_buySedemption` | `{"series":[{"name":"期间申购",...},{"name":"期间赎回"},{"name":"总份额"}],"categories":[...]}` | 期间申赎 |
| `Data_currentFundManager` | `[{name, star, workTime, fundSize, power:{...}, profit:{...}}]` | 现任基金经理 |
| `Data_rateInSimilarPersent` | `[[ts, 百分比], ...]` | 同类排名百分比走势 |

### 8.4 时间戳换算（**易错**）

`x` 是**北京时间零点**的毫秒时间戳，直接按 UTC 取日期会**差一天**，必须按 UTC+8：

```
1344960000000 ms → 2012-08-15（270042 成立日）
```

实现提示：按 `Asia/Shanghai`（UTC+8）格式化，**不要**用本地时区或 UTC。

### 8.5 样本（270042，2026-09-11）

```
净值走势   3392 点，2012-08-15(1.0) → 2026-09-11(8.1177)
规模变动   93.14 → 106.52 → 108.44 → 97.16 → 122.23 亿元（近 5 个季度）
资产配置   股票 0% / 债券 0% / 现金 9.04% / 净资产 208.63 亿元
持有人     机构 0.12% / 个人 99.88%
```

> 联接基金（FOF）的「股票占净比」为 0，因为它持有的是 ETF 份额而非股票，
> 需结合接口 I 的 `ETFCODE` 理解。

## 13. 综合注意事项

1. **合规**：以上均为非官方接口，请控制频率（建议 ≥ 30 分钟一次），禁止高频轮询。
2. **免责**：限购额度最终以基金公司公告为准，工具输出仅供参考。
3. **时效**：
   - 接口 A 的 `showday` 显示数据日期，QDII 净值天然滞后（实测 `09-11` vs 当日 `09-14`）
   - 接口 A 的净值日期只有 `MM-DD`，**跨年需自行补年份**；接口 B 的 `FSRQ` 有完整年份
4. **编码**：接口 A / E 均为 UTF-8；**接口 E 与 G 带 BOM**，需按 `utf-8-sig` 解码
5. **容错**：所有状态字段都可能为空字符串；`MINSG/MAXSG` 可能为 `"--"`；`日累计限定金额` 可能是 `0`
6. **时区**：接口 G 的时间戳是**北京时间零点**，必须按 UTC+8 换算，否则日期差一天
7. **CORS（决定架构的关键结论）**：

   | 接口 | CORS | 能否支撑前端 |
   |---|---|---|
   | A. 全市场申购状态 | ❌ **无任何 `Access-Control-*` 响应头** | 前端拿不到 735 只的列表 |
   | B. 单基金实时信息 | ✅ `*` | 只能一次查一只，无法列全量 |

   → **列全量必须用接口 A，而接口 A 不支持跨域**，因此本项目必须自建后端
   （不能用「纯静态页 + 定时落 JSON」的方案，除非把全量拉取放到 CI 里）。
8. **可达性**：`fund.eastmoney.com` / `fundf10.eastmoney.com` / `api.fund.eastmoney.com` /
   `fundmobapi.eastmoney.com` 实测均可在无代理环境直接访问；`push2` 主备切换见 §7.5
