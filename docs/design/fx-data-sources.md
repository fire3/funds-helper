# 汇率上游接口调研（新浪财经外汇）

> 本工具（`fx`）的上游是**新浪财经**，与 QDII / 美元份额用的天天基金 / 东方财富无关。
>
> 调研方式：直接请求接口 + 用**已知历史事件交叉验证字段语义**（不是照抄文档）。
> 采集日期：2026-09-19（数据截至 2026-09-18）。

---

## 1. 为什么不用东方财富

东财确实有汇率行情，但**历史 K 线拿不到**：

| 候选 | 结果 |
|---|---|
| `push2.eastmoney.com/api/qt/clist/get?fs=m:120` | ✅ 可用：25 个「中间价」货币对（`USDCNYC` = 美元人民币中间价，secid `120.USDCNYC`） |
| `push2.eastmoney.com/api/qt/stock/get?secid=120.USDCNYC` | ✅ 可用：只给**当前**值与昨收（`f43=67521` → 6.7521） |
| `push2his.eastmoney.com/api/qt/stock/kline/get?secid=120.USDCNYC` | ❌ 返回空（`kd` 无效），且该 host 在测试环境解析到 IPv6 后连接失败 |

结论：东财只能给「今天」，本工具要的是**数年波动**，因此另找数据源。
（东财中间价可作为后续「中间价对照」的补充，见 `fx-tool.md` §9。）

## 2. 为什么不用免费汇率 API（frankfurter / exchangerate.host）

`https://api.frankfurter.app/...` 实测可用且无需 key，但：

- 它是**欧洲央行参考汇率**（每日 16:00 CET 定盘），不是国内口径的美元兑人民币即期汇率
- 国内访问稳定性不如国内站点
- 对「人民币汇率」这个命题，口径偏差比省事先重要

**本项目选定的实时性/口径优先级：国内口径即期汇率 > 泛用的 ECB 参考汇率。**

## 3. 选定接口：新浪外汇日线

```
GET https://vip.stock.finance.sina.com.cn/forex/api/jsonp.php/x/NewForexService.getDayKLine
    ?symbol=fx_susdcny
Referer: https://finance.sina.com.cn/     ← 实测可省略，但保留更稳妥
```

- `symbol=fx_susdcny` = **在岸美元兑人民币即期汇率**（`fx_s` 前缀 + `usdcny`）
- 无需 token / cookie；实测无 `Referer` 也返回 200

### 3.1 响应形态

```text
/*<script>location.href='//sina.com';</script>*/
x("1994-08-30,8.5616,8.5616,8.5616,8.5616,|1994-08-31,8.5591,8.5591,8.5591,8.5591,|…|2026-09-18,6.7067,6.6856,6.7074,6.6984")
```

- **JSONP**：外壳是 `x("…")`，载荷是**一个 JS 字符串**，内部用 `|` 分隔行、`,` 分隔列
- **一次返回全量历史**：实测 **8021 行 / 320,893 字节**，起始 `1994-08-30`
- 编码为 **ASCII**（纯数字与日期）——因此**无需**给 `HttpClient` 增加 GBK 支持
  （`architecture.md` §6.1 的编码缺口在本工具不构成阻塞）

### 3.2 字段序：`date,open,low,high,close`

这是本次调研**唯一需要推断**的部分，用两个已知历史事件交叉验证：

| 日期 | 实测行 | 已知事实 | 推断 |
|---|---|---|---|
| 2005-07-21 → 07-22 | `8.2765` → `8.1100` | 2005-07-21 晚宣布汇改，7-22 起一次性升值至 8.11 | 收盘价语义正确 |
| 2015-08-11 | `6.3101,6.2856,6.3286,6.3248` | 811 汇改：中间价 6.1162→6.2298，即期跳升逾 1% | 第 3 列 **< 第 4 列** → 只能是 `low,high` 而非 `high,low` |
| 2015-08-10 → 08-11 | `6.2096` → `6.3248` | 即期当日大幅跳升 | 第 5 列为**收盘价** |
| 2015-08-12 → 08-13 | `6.3870` 收 → `6.3870` 开 | 外汇市场连续报价、无跳空 | 第 2 列为**开盘价** |

> 若按直觉的 `date,open,high,low,close` 解析，2015-08-11 会得到「最高 6.2856 < 最低 6.3286」
> 这种不可能的组合 —— 这正是本项目坚持「用真实事件验证字段语义」的原因。

**1994–2005 的早期行四列完全相同**（如 `8.5616,8.5616,8.5616,8.5616`）：
该时期是固定/区间汇率，只有单一报价。解析层照常保留数字，
但 `core` 的年度统计以**收盘价**为准，不受影响。

### 3.3 实测数据特征（用于护栏取值）

| 项 | 实测 | 用途 |
|---|---|---|
| 行数 | **8021** | 护栏 `FX_MIN_EXPECTED = 5000` |
| 起始日期 | `1994-08-30` | — |
| 最新日期 | `2026-09-18` | `dataDate` |
| 历史区间 | 最高 `8.5616`（1994-08-30）→ 最低 `6.0412`（2014-01-14，人民币最强的时点） | 数十年波动确实可见，且极值时点与史实吻合 |
| 频率 | 工作日（无周末行） | 区间按自然日回看即可 |

### 3.4 明确不做的接口

```
GET https://hq.sinajs.cn/list=fx_susdcny        ← 实时行情
Referer: https://finance.sina.com.cn/           ← 必需（无 Referer 返回 403）
```

返回 **GBK** 编码，且字段语义未能确认：

```text
var hq_str_fx_susdcny="02:56:00,6.6970,6.6984,6.6984,53.0,6.7005,6.7015,6.6962,6.6984,
在岸人民币,0.0000,0.0000,0.0053,此行情由新浪财经计算得出,0.0000,0.0000,,2026-09-19";
```

第 5 个字段是 `53.0`（量？）而非价格，无法用「开高低收」套用；要确认必须再找权威文档。
**收益不足以支撑风险** —— 日线序列已包含当日 K 线，且本工具定位是「数年波动」而非「此刻价格」。

## 4. 复现方式

```bash
curl -s 'https://vip.stock.finance.sina.com.cn/forex/api/jsonp.php/x/NewForexService.getDayKLine?symbol=fx_susdcny' \
  | tr '|' '\n' | grep -E '2005-07-2[12]|2015-08-1[01]'
# 2005-07-21,8.2765,…   2005-07-22,8.1100,…     ← 汇改
# 2015-08-10,6.2096,…   2015-08-11,6.3101,6.2856,6.3286,6.3248,…   ← 811 汇改
```
