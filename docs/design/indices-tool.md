# 国际行情工具（indices）设计说明

> 上游选型与实测依据见 [`global-index-data-sources.md`](./global-index-data-sources.md)。
> 本文只记录**实现决策**：接口、schema、任务、护栏。实施日期：2026-09-26。

---

## 1. 定位

回答一个问题：**「美股、港股、海外主要指数现在多少？这段时间是怎么走的？」**

- 概览：28 个主要指数的最新收盘与日涨跌，按地区分组（美国/中国香港/亚太/欧洲/美洲），
  逐条附当日今开/最高/最低；支持按涨跌幅排序（写进 URL）
- 单指数：日线走势 + 区间涨跌 + 年度表现（与「人民币汇率」页同构的统计口径）
- 数据时效：`daily`（日频收盘价；免费源都是延迟行情，**不声称实时**）

## 2. 接口

| 路径 | 说明 |
|---|---|
| `GET /api/tools/indices/overview` | 全部指数最新收盘（按地区分组），`?refresh=1` 强刷缓存 |
| `GET /api/tools/indices/dataset?code=SPX&range=5y` | 单指数走势 + 统计；未知 code/区间回落默认（`SPX`/`5y`） |
| `POST /api/tools/indices/refresh` | 手动触发 `indices.daily`（走调度器，留 `job_run` 记录） |

URL 状态：`/tools/indices?code=HSTECH&range=3y` —— 选中指数与区间都可分享。

## 3. 数据流与降级

```
Yahoo（主，覆盖全部 28 个）──成功──┐
        │ 429/网络/404              │
东财 push2his（K 线备源，缺 4 个）──┼──→ index_quote_daily（SQLite，唯一键 code+data_date）
        │ 不可用/无此指数            │         │
腾讯 ifzq（应急，美/港 5 个）──────┤         进程内 TTL 缓存（indices.overview / indices.dataset.{code}）
        │ 不可用/无此指数            │                │
新浪 gi 日线（第四源，19 个）──────┘                │
                                              API 响应（freshness 契约）
东财 clist 批量实时 ──→ 概览缺失补齐（只补库里没有的指数，不写库）
```

- **四源编排在** `apps/server/src/data-sources/indices.ts`；`sources` 只做单上游解析。
- 东财缺纳指 100 / 罗素 / VIX / 恒生科技（注册表 `em: null`），
  这些指数只能靠 Yahoo —— Yahoo 失败且本地无数据时走腾讯/新浪/实时补齐/降级（503 / stale）。
  ⚠️ 2026-09-27 勘误：恒生国企/TSX 不缺，是代码猜错（正确 `100.HSCEI`/`100.TSX`，见报告 §14）。
- **腾讯是「应急」不是「备选」**：只覆盖美/港 5 个、K 线上限 1600 行，但国内直连最稳。
  实战记录：2026-09-26 晚「Yahoo 429 + 东财 503」双故障窗口中，5 个头部指数靠腾讯未断。
- **部分失败不算失败**：`captureAll` 单指数故障记入 `failed[]`，其余照常落库；
  全军覆没才抛 `UpstreamError`。
- 东财 K 线端点 **HTTP 在前、HTTPS 兜底**（HTTPS 间歇 000 是实测事实，见报告 §5.2）。

## 4. 关键护栏（都有测试钉住）

| 护栏 | 位置 | 断言 |
|---|---|---|
| 静态符号映射表 | `core/indices/registry.test.ts` | 东财恰好缺 4 个；腾讯恰好覆盖 5 个；新浪恰好缺美/港 9 个；新指数（斯托克50/SMI/MIB/IBEX/AEX/NZ50）四源代码齐全；`100.NDX` 登记在「纳斯达克综合」（同名陷阱）；恒生科技用 `HSTECH.HK` |
| 区间口径与 fx 同源 | 编译期 + `contract.test.ts` | `INDEX_RANGE_KEYS`/`INDEX_INTERVAL_KEYS` 直接传给 fx 序列函数，字面量不同则**编译失败** |
| **跨源新鲜度** | `service.captureCode` | 本次收盘与库里另一源同日收盘偏差 >0.5% → warn 日志（新浪陈旧 feed 教训，报告 §7.1） |
| Yahoo 429 退避 | `sources/indices/yahoo.ts` | 首次 429 退避 20~30s 一次；冷却窗口全组共享，避免 28 指数排队撞墙；仍失败交备源 |
| **批量实时缺失补齐** | `service.buildOverview` | 只补库里**没有**的指数、不覆盖已有行情（实时值不是收盘价）；clist 失败静默降级；本地+实时都空才 503；交易日按交易所时区推导（`core/indices/session.test.ts`） |
| 结构级严格 | 两侧 parse | Yahoo 数组长度不齐 / 东财列数变化 → `ParseError`（502 显式暴露） |
| 行级宽松 | 两侧 parse | 缺收盘价/日期非法的行跳过并计数，不整批失败 |
| 非上游错误不伪装降级 | `service` | DB/编程错误抛 500，只有 `UpstreamError` 才走 503/stale |

## 5. Schema 与任务

- 迁移 `0013-index-quote`：单表 `index_quote_daily(code, data_date, captured_at, source, ohlc)`；
  指数元数据是**代码里的静态注册表**，不落库（上游代码变了改代码即可）。
- 任务 `indices.daily`：cron `20 */3 * * *`（每 3 小时，`runOnBoot`）。
  依据：数据是日频收盘价，各市场收盘时刻（北京时间）港 16:00 / 日 15:00 / 欧 ~23:00 / 美次日 04:00–05:00；
  增量抓取（每指数回看 10 天修订余量）请求量很小。分钟位错开 20 分，避免与其它任务整点撞车。
- 回填：库中无数据时 `period1=0` 全量（标普 14305 行 / 1.5 MB，东财道指 9179 行 / 1990 起）。

## 6. 运行环境注意：需要代理的机器

本仓库开发机出网必须走代理（`http_proxy`/`https_proxy`），而 **Node 的 fetch 默认不读
环境代理**（curl 读）—— 症状是上游 `fetch failed / ETIMEDOUT`。解法与 news 工具相同、
零代码：`NODE_USE_ENV_PROXY=1 pnpm dev`（Node ≥ 24，见 `.env.example` 的网络说明段）。
部署机可直连国际网络时无需此变量。与本工具相关的实测：无代理时 Yahoo 直连超时、
东财 `push2his` 的抖动与代理无关（见报告 §5.2）。

## 7. 与调研报告的偏差记录

- 报告建议「每日一次增量 + 盘中按需」，实现为**每 3 小时增量 + 按需**：
  与 fx 同频，代价可忽略（增量响应为每指数两周数据），换来「美股收盘后 3 小时内必然有当日数据」。
- 腾讯应急源**已实现**（原计划「若 Yahoo 长期限流再补」—— 2026-09-26 晚条件成立即实装）：
  链路 Yahoo → 东财 → 腾讯，只对注册表 `tencent` 非空的 5 个指数生效。
  2026-09-27 又追加了第四源新浪 gi 与东财批量实时补齐（见 §9）。
- 补充调研（报告 §13，2026-09-26 晚）：雪球（WAF+token 登录墙）、百度股市通（验证码墙）、
  同花顺/网易（502/503）、券商系（授权墙）、集思录（不可达且无此业务）全部否决；
  **FT Markets 两接口匿名可用且收盘价与快照逐分不差**，登记为第三备源候选（未实现）；
  华尔街见闻 API 可达但需逆向 SPA，留作后续观察。
- 盘中分时（1m/5m）未做：定位是 `daily`，Yahoo 的分时能力留给未来。

## 8. 真实上游 E2E 实录（2026-09-26 晚，双故障窗口）

实施当晚正好赶上「Yahoo 持续 429 + 东财 push2his 持续 503」的真实双故障窗口，
三源链路在真实网络下被完整验证（临时库 + `NODE_USE_ENV_PROXY=1`）：

| 步骤 | 结果 |
|---|---|
| `dataset?code=SPX` | 200，37.9s：Yahoo 退避探测 → 东财 503 重试 → **腾讯接住**，`freshness.source=tencent`，1600 根（2020-05-14 起），9/25 收盘 7743.41 与快照一致 |
| `overview` 空库首访 | 200，5m41s（22 指数 × 三源竞跑的病理代价）：**5 个头部指数（SPX/IXIC/NDX/DJI/HSI）经腾讯入库**，价格与快照逐分一致；17 个进 `failed[]` |
| `dataset?code=hstech`（小写） | 归一化到 HSTECH；503，detail 完整列出三源失败原因（yahoo 429 / 东财 em=null / 腾讯 tencent=null），25s —— 冷却窗口生效，全组只付一次探测成本 |
| 落库检查 | `source` 列逐行可信；NDX 实测只有 1 根（腾讯 `usNDX` K 线怪癖，见注册表注释）—— Yahoo 恢复后 upsert 自愈 |

已知边界（当前实现的取舍）：

- 双故障窗口下 `overview` 首访可达分钟级（东财 503 的 2×重试 × 2 端点 × 17 指数是大头）；
  正常窗口（任一源健康）是秒级。后台任务 `20 */3 * * *` 可接受；交互式首访可后续优化
  （如只补缺失指数 + 整体超时熔断）。
- 概览对「部分失败」不置 `stale`（按设计：陈旧但真实 > 错误页），失败明细见 `/refresh`
  响应与 `job_run`；未来可在 freshness 里带 `failedCount`。

## 9. 第四源、批量实时与页面增强（2026-09-27，akshare 复盘）

> 触发：复盘 [akshare](https://github.com/akfamily/akshare) 的国际行情模块，把可借鉴的
> 接口逐个实测。详实测证据与覆盖矩阵更新见报告 §14。当日正赶上
> 「东财 push2his 整体故障 + Yahoo 直连不通（需代理且 429）」的真实双故障窗口。

### 9.1 从 akshare 借到的三样东西

| akshare 模块 | 借到什么 | 实测结论 |
|---|---|---|
| `index/index_global_sina.py` | 新日线接口 `gi.finance.sina.com.cn/hq/daily` | ✅ 实装为**第四源**：19 指数、OHLC 齐、1000 行上限（约 4 年）、数据新鲜（与 Yahoo 逐日一致） |
| `index/index_global_em.py` | 东财 clist 的 `fs=i:100.<代码>` **显式清单**写法 | ✅ 实装为**批量实时缺失补齐**：单请求 50 指数（含今开/高/低/昨收）；报告 §5.2 的「clist 全空」是通配组合的锅 |
| `index/cons.py` 符号表 | 东财正确代码 | ✅ 勘误两处：恒国企 `100.HSCEI`、加拿大 `100.TSX`（旧猜法 `100.HSCE`/`100.GSPTSE` 不存在，误判「东财缺 6 个」→ 实际缺 4 个） |

### 9.2 新增与勘误（注册表）

- **新增 6 个指数**（三源齐备才收录）：欧洲斯托克50、瑞士SMI、意大利MIB、西班牙IBEX、
  荷兰AEX（europe），新西兰NZX50（apac）；`INDEX_REGISTRY` 22 → 28。
- Yahoo 符号坑：意大利 MIB 是 `FTSEMIB.MI`（`^FTMIB` 无数据）、新西兰是 `^NZ50`
  （`^NZ55` 无数据）；新浪符号是自家体系（`UKX`/`NKY`/`TWJQ`/`SWI20`/`NZ250`…）。
- 新浪恰好缺**美股与恒指系 9 个**（`INX/DJI/NDX/HSI/HSCE/HSTECH` 实测 not found）——
  与腾讯（只覆盖美/港 5 个）互补而非重叠，降级链里两者的顺序不影响覆盖。

### 9.3 批量实时「缺失补齐」语义（与日线的本质区别）

- **只补库里没有的指数**（首次加载 / 日线全链路失败），**不覆盖**已有行情 ——
  实时值不是收盘价，覆盖会污染区间/年度统计；库里数据永远优先。
- clist 没有交易日期字段：日期按 `core/indices/session.ts` 推导
  （交易所时区的「今天」，周末回退周五）。**节假日会标错日期**，只影响未入库指数的
  卡片日期，日线恢复后自愈；不引第三方交易日历。
- 503 条件收紧：从「本地无数据且日线失败」改为「本地无数据、日线失败、
  **且批量实时也没补上**」—— 实测当日 yahoo+push2his 双挂时概览仍 200 完整返回。

### 9.4 页面

- 概览卡片增加**当日今开/最高/最低**（`IndexQuote` 契约新增 `open/high/low`，
  库里行与实时报价都带）。
- 概览支持**按涨跌幅排序**（各地区内降序、缺失垫底），状态 `sort=chg` 写进 URL。
- 来源角标中文化：东财/腾讯/新浪（Yahoo 是主源不标）。

### 9.5 真实故障窗口 E2E 实录（2026-09-27）

| 源 | 结果 |
|---|---|
| Yahoo（代理） | 首请求 429 → 冷却窗口生效、后续快速失败（实现代理 IP 被限） |
| 东财 K 线 push2his | ❌ 全挂（http 空回复 / https 000，代理下同样） |
| **新浪 gi 第四源** | ✅ **19/19 成功** —— 当日欧/亚指数全部由它接住 |
| 腾讯应急源 | ✅ 5/5 成功（美/港头部指数） |
| **东财 clist 批量实时** | ✅ **24/24**（全部有 em 代码的指数，含勘误后的 HSCEI/TSX/NZ50/SMI/MIB/IBEX/AEX/SX5E） |
| 交叉验证 | 新浪 vs clist 19 项重叠指数收盘偏差 **全部 ≤0.001%** |

⇒ 四源 + 实时补齐的组合下，**28 个指数在「双源全挂」当天依然每个都有数据可用**。
